# ADR-013 — Integrar API Corporativa de Pedidos

## Contexto

A aplicação requer acesso a informações corporativas de pedidos sem depender de dados fabricados ou desatualizados.

## Decisão

Utilizar uma API HTTP simulada (*mock*) independente, respaldada por *fixtures* JSON, e integrá-la por meio da porta (*port*) `OrderReader` existente utilizando a Fetch API nativa do Node.js.

Preservar a validação de propriedade (*ownership*) na camada de aplicação.

### Controles de segurança
* Autenticação serviço a serviço (*service-to-service*) utilizando um token compartilhado de demonstração.
* Identidade confiável do cliente fornecida pelo backend.
* Recuperação de pedidos restrita ao escopo do cliente (*customer-scoped*).
* Validação de resposta em tempo de execução (*runtime*) com Zod.
* *Timeout* de requisição de três segundos.
* Tamanho máximo de resposta de 16 KB.
* Rejeição de redirecionamentos (*redirects*).
* Respostas sanitizadas para falhas de serviços *upstream*.
* Respostas consistentes para pedidos inexistentes e não autorizados.

## Justificativa

O adaptador HTTP fornece uma fronteira de integração realista sem introduzir dependências desnecessárias ou alterar as regras de negócio existentes.

## Consequências

* A API simulada (*mock*) é restrita à demonstração local.
* O adaptador em memória (*in-memory adapter*) permanece disponível para testes automatizados isolados.
* A integração em produção exigiria TLS, credenciais de serviço gerenciadas e controles operacionais adicionais.
* O *endpoint* de cancelamento será implementado junto ao fluxo de confirmação e idempotência.
