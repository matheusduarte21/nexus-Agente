# ADR-015 — Ingestão e Recuperação de Conhecimento

## Contexto

A Nexus Commerce requer ingestão controlada de conhecimento e recuperação confiável de documentos de políticas corporativas.

## Decisão

* Executar a ingestão de documentos por meio de uma CLI local dedicada.
* Utilizar um papel (*role*) restrito de banco de dados para a ingestão de conhecimento.
* Gerar *embeddings* em lotes (*batches*) de 32.
* Ignorar documentos ativos inalterados com base no hash do conteúdo e no modelo de *embedding*.
* Persistir versões de documentos e fragmentos (*chunks*) de forma transacional.
* Serializar escritas concorrentes para a mesma fonte utilizando bloqueios consultivos em nível de transação (*transaction-level advisory locks*).
* Utilizar similaridade de cosseno exata (*exact cosine similarity*) para recuperação vetorial.
* Utilizar a Busca de Texto Completo (*Full-Text Search*) do PostgreSQL com configuração em português e índice GIN.
* Recuperar apenas documentos ativos associados ao modelo de *embedding* configurado.

### Controles de segurança
* Credenciais separadas de banco de dados para ingestão e tempo de execução (*runtime*).
* Nenhum *endpoint* público para upload ou ingestão de documentos.
* Consultas parametrizadas ao banco de dados.
* Contagem limitada de resultados na recuperação.
* Ativação transacional de documentos.
* Mensagens de falha da CLI sanitizadas.
* Nenhum fallback automático entre provedores de *embedding*.

## Consequências

* A ingestão de documentos deve ser executada separadamente da API conversacional.
* A alteração de modelos de *embedding* exige reingestão.
* A alteração dos parâmetros de fragmentação (*chunking*) pode exigir uma estratégia explícita de reingestão.
* A remoção de um arquivo local não desativa automaticamente o documento armazenado.
* As pontuações (*scores*) vetoriais e lexicais não são diretamente comparáveis.
* O ranqueamento híbrido e a seleção de evidências serão implementados na próxima etapa.
