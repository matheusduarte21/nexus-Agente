# ADR-006 — Adoção de Integração Contínua e Quality Gates Automatizados

## Contexto

A Nexus Commerce requer um processo de desenvolvimento seguro e sustentável, capaz de identificar violações arquiteturais, defeitos de software, dependências vulneráveis e exposição acidental de credenciais.

A revisão manual de código por si só não oferece consistência ou reprodutibilidade suficientes.

## Decisão

Adotaremos o **GitHub Actions** como plataforma de integração contínua (CI).

O pipeline do backend aplicará verificações automatizadas de qualidade e segurança.

### Controles de qualidade
* Modo estrito (*strict mode*) e verificação de tipos do TypeScript.
* Análise estática com ESLint.
* Verificação de formatação com Prettier.
* Fiscalização arquitetural com Dependency Cruiser.
* Testes automatizados unitários e ponta a ponta (*end-to-end*).
* Limites mínimos de cobertura de código (*code coverage*).
* Instalação reprodutível de dependências utilizando `npm ci`.
* Varredura de vulnerabilidades em dependências utilizando `npm audit`.
* Varredura de segredos (*secret scanning*) utilizando Gitleaks.

### Fluxo de desenvolvimento
O **Husky** fornecerá *hooks* locais do Git.

O **Commitlint** aplicará o padrão *Conventional Commits* localmente.

O **GitHub Actions** permanecerá como o mecanismo oficial de verificação automatizada para integração.

Onde suportado, verificações de status obrigatórias (*required status checks*) protegerão a branch `main`.

### Controles de segurança
* Permissões somente leitura (*read-only*) no GitHub Actions.
* *Actions* do GitHub fixadas (*pinned*) aos SHAs completos dos commits.
* Imagens de contêiner fixadas a *digests* imutáveis.
* Nenhuma credencial de produção exigida pelos testes automatizados.
* Vulnerabilidades altas (*high*) e críticas (*critical*) em dependências reprovam o *job* de segurança.
* A varredura de segredos inclui o histórico do Git.
* Atualizações de dependências são revisadas antes da integração.

## Alternativas consideradas

* Apenas verificação manual.
* *Hooks* locais do Git sem integração contínua.
* Plataformas externas de CI.
* Plataformas corporativas abrangentes de DevSecOps.

## Justificativa

O GitHub Actions fornece verificação automatizada e reprodutível sem introduzir infraestrutura adicional.

Os *hooks* locais melhoram a velocidade de feedback, enquanto as verificações centralizadas reduzem a dependência dos ambientes individuais dos desenvolvedores.

A varredura automatizada de segurança proporciona identificação precoce de vulnerabilidades conhecidas e exposição de credenciais.

## Consequências

* A configuração do pipeline e as versões das dependências exigem manutenção contínua.
* Vulnerabilidades conhecidas podem impedir temporariamente a integração até que uma correção esteja disponível.
* A cobertura de código não garante a corretude (*correctness*).
* A varredura automatizada não garante a ausência de vulnerabilidades.
* Os *hooks* locais do Git podem ser contornados e não devem ser tratados como fronteiras de segurança.

## Verificação

Os *jobs* de qualidade e segurança devem ser executados com sucesso antes que os controles correspondentes sejam considerados verificados.

Recursos futuros de autenticação, autorização, execução de agentes e cancelamento devem incluir testes de segurança determinísticos.
